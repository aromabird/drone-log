# D-log（ディーログ）

飛行記録・日常点検・機体管理を1画面で行う、静的ホスティング向けの Web アプリ（PWA）です。
Google Apps Script（GAS）と Google スプレッドシートは使用しません。

- フロントエンド: `index.html`（Tailwind CSS CDN + Vanilla JS。ビルド不要）
- データ保存: ブラウザの `localStorage`（端末ごと）
- 重い処理: `drone-log-bff`（FastAPI）に委譲
  - DJI ログ（`.txt`）の解析
  - 飛行日誌 Excel（様式1）の生成
  - 周辺インフラ（送電線・鉄塔）の判定
- 公開 URL: `https://aromabird.github.io/drone-log/`
- リポジトリ: [`aromabird/drone-log`](https://github.com/aromabird/drone-log)
- 記録様式: 国交省「無人航空機の飛行日誌の取扱要領」様式1〜3 に準拠した列構成

## 1. 主な機能

| タブ | できること |
|---|---|
| 飛行を記録 | **3フェーズ**（①計画・現場環境 → ②飛行前点検 → ③実績・飛行後点検）で入力。②の時点で **「飛行前点検を保存（フライト待機）」** ができ、フェーズ1・2は自動で折りたたまれ、着陸後は日誌／起動バナーから**フェーズ3で再開**して完了保存。飛行情報（様式1）と日常点検（様式2・13項目・前後2回）を記録。離着陸時刻から飛行時間を自動計算（日跨ぎ対応）。現在時刻（JST）のワンタップ打刻、GPS による現在地＋住所の取得を主導線にし、住所・緯度経度の手動入力は必要なときだけ展開（折りたたみ）。離着陸座標から天候・風速・海抜標高・DID を取得して飛行適性を判定。周辺マップ（地理院タイル）を表示し、その画像を含めた AI 診断に対応。周辺インフラ（送電線・鉄塔）のリスクチェック。特定飛行10項目と立入管理措置からカテゴリーⅠ/ⅡA/ⅡB/Ⅲを自動判定。DJI ログ（.txt）の取り込み。入力の自動下書き（localStorage）とクリア。 |
| 日誌 | 期間・機体・キーワードで検索、飛行ごとの点検結果の確認、様式1 CSV / 様式2・3 CSV / 飛行日誌 Excel（BFF）の出力 |
| 機体管理 | 機体・操縦者の登録/編集、技能証明（資格区分・有効期限・限定解除）、20時間（1200分）基準の点検アラート、20時間定期点検・修理の記録 |
| ヘルプ | 主な機能、現場の入力フロー（GPS 優先）、空域（DID・空港周辺）とカテゴリーの自動判定、気象情報の取得元とフェイルセーフ、法定帳票（Excel）出力、データプライバシー、基本的な使い方 |
| 設定 | BFF の接続先（localStorage に保存）、操縦者マスタの技能証明（一等/二等/なし、有効期限、目視外/夜間/25kg以上の限定解除）、データの手動同期（BFFの `data/backup.json` へ保存・復元） |

屋外での視認性を優先し、アプリ全体の文字サイズを **130% に固定**しています。

### 離陸場所の入力フロー（GPS 優先）

現場のモバイル操作（片手・手袋・日差し）を前提に、離陸場所の入力は **GPS を主導線** にしています。

- 「📍 現在地から住所を取得 (GPS)」が離陸場所のメインアクション（全幅・高さ 3rem 以上）です。
  タップすると端末の現在地から緯度・経度を入れ、国土地理院の住所検索／BFF の逆ジオコーディングで住所を補完します。
- **住所の手動入力**（「手動で入力・修正する」）と**緯度・経度の手動入力**（「緯度・経度を手動で入力」）は
  `<details>` で折りたたみ、**既定は閉じています**。現場では GPS だけで完結し、必要なときだけ開く運用です。
- 折りたたみが閉じていても現在値が分かるよう、離陸場所の下に **要約行** を表示します
  （例: 「千葉県香取市小見川 ・ 座標 35.900000, 140.500000」）。
  GPS・座標検索・貼り付け・DJI ログ取り込み・保存のたびに更新されます。
- バリデーションエラーや GPS 取得失敗時は、該当の折りたたみを **自動で開いて**から入力欄へフォーカスします。
- 住所・座標は「座標検索」「`35.681236, 139.767125` の貼り付け」「DJI ログ（.txt）取り込み」からも入力できます。

### 空域と飛行カテゴリーの自動判定

- **空域の自動判定**: BFF `GET /api/check-infrastructure` が、国土地理院 **DID2020** タイル（人口集中地区）と
  同梱の **空港データ**（OurAirports）から、DID と空港等の周辺（6km 以内＝該当 / 12km 以内＝近接）を判定します。
- **チェックの自動追加（追加のみ）**: DID・空港周辺に該当すると、特定飛行10項目の該当行へ自動でチェックを入れます。
  ユーザーが手動で外したチェックをシステムが戻すことはありません。
- **カテゴリー下限の自動引き上げ**: 空域（DID → **ⅡB**、空港周辺 → **ⅡA**）や、
  送電線・鉄塔などの物理インフラが検知された場合は、判定カードに
  「空域の下限: カテゴリーⅡB以上」のように **下限** を表示します。
  最終カテゴリー（Ⅰ / ⅡA / ⅡB / Ⅲ）は、これに機体重量（25kg 以上）と立入管理措置を加えて再計算されます。
  送電線・鉄塔は法令上の特定飛行ではないため、法令の下限とは分けて「安全上の要確認: カテゴリーⅡB相当」と表示します。
- **30m 推論**: DID（人口集中地区）に該当した場合は、実運用上ふつう第三者・物件から 30m の距離を確保できないため、
  **「人または物件から30m未満」にも自動でチェック** を入れます（追加のみ・解除はしません）。
- 判定できなかった場合（時間切れ・DID 不明）は「異常なし」ではなく **「判定不能」** と表示し、DIPS での確認を促します。

### 気象情報（BFF 集約とフェイルセーフ）

天候・風速・突風は **BFF の `GET /api/weather`** から取得します。
PWA が外部の気象 API を直接叩くのは、**BFF に接続できないときだけ**です。

- **取得元の優先順**: ① 気象庁アメダス（国内の実測値・10分更新、最寄りの風観測所）→ ② Open-Meteo（WMO 天候コード・突風）。
- **BFF 側のフェイルセーフ**: 取得元ごとに時間予算を区切っており（主系 4 秒・代替の取り分 3 秒を必ず残す）、
  気象庁がハングしても全体 8 秒の上限内で Open-Meteo に切り替わります。主系のタイムアウトは再試行しません
  （残り時間を代替へ回すため）。全取得元が失敗した場合も、30 分以内のキャッシュがあれば
  `stale=true` の **「参考値」** として 200 で返します。
- **表示**: 出典（例: 気象庁 アメダス（東京観測所・約1.9km）／Open-Meteo）、観測時刻、補足（観測所を切り替えた理由など）を表示します。
  参考値のときは「※取得元が応答しないため直近の値を表示（参考値）」と明記します。
  風速が取得できない場合は「良好」と誤表示せず **判定不可（UNKNOWN）** とし、現地確認を促します。
- **多層フォールバック**: BFF → Open-Meteo 直接取得（8 秒で打ち切り）→「取得できません」。
  気象が取れなくても、標高・DID の表示、記録の保存、CSV / Excel 出力は継続します。

### AI 安全フライト診断について

飛行を記録タブの「地図でAI診断」「現場写真でAI診断」「周辺情報のみでAI診断」は、BFF の `POST /api/diagnose`
を経由して **Gemini API** で飛行前の安全診断文を生成します。

- 送信するのは飛行計画・気象・標高・DID・周辺インフラ・機体・資格区分（＋任意の周辺マップ画像 / 現場写真）です。
  操縦者の氏名・連絡先は送信しません。
- 「地図でAI診断」は、入力座標の周辺マップ（国土地理院タイル・空中写真/淡色地図）を
  `html2canvas` で JPEG 化してから送ります。地図は変更のたびに再描画され、AI は地形・道路・
  建物・鉄塔/送電線などを画像から読み取って診断します。
- 現場写真はブラウザ内で長辺 1200px の JPEG に圧縮してから送ります。
- API キーは BFF の `.env` のみで管理し、ブラウザには置きません。
- 診断文はプレーンテキストとして描画し、Markdown / HTML としては解釈しません。
- BFF が未設定・停止している場合はエラーメッセージを表示します（記録・CSV は影響を受けません）。
- 診断は助言であり、**最終判断は操縦者が行う**前提です。特定飛行区分の自動判定には反映しません。

### フェーズ運用（飛行前点検の途中保存と再開）

現場では「点検 → 離陸 → 着陸 → 記録」と時間が空くため、入力画面を業務フローに沿った3フェーズに分けています。

| フェーズ | 内容 |
|---|---|
| フェーズ1 | 計画・現場環境（離陸場所・GPS・「現場環境からリスク判定」・特定飛行・AI診断） |
| フェーズ2 | 飛行前点検（13項目）＋**「飛行前点検を保存（フライト待機）」** |
| フェーズ3 | 離着陸時刻・飛行時間・**飛行後点検**・特記事項 → **「保存する（完了）」** |

- フェーズ2で保存すると `status: "pre_flight_ready"` として記録され、フェーズ1・2が自動で折りたたまれます。
  summary には `✅ 飛行前点検済 10:15 / 風速2.1m/s` のように要約を表示します。
- 待機保存・完了保存のたびに BFF `/api/flight-records` へ同期します（失敗時は端末保存のまま「BFF未同期」表示）。
- 日誌一覧の「⏳ 飛行待機」カード、または起動時の再開バナーから、**フェーズ3だけ**を開いて再開できます。
  再開後の保存は同じ `flightId` を更新し、`status: "completed"` になります（点検は前後2件）。
- `status` を持たない既存データは `completed` として扱います（後方互換）。
- フライト待機の記録は飛行回数・飛行時間の統計には含めません（日誌一覧には残ります）。
- 入力は 600ms デバウンスで `localStorage`（`drone-log:draft:v1`）へ自動退避し、次回起動時に「復元 / 破棄」を選べます。
  保存成功・入力をクリア・破棄で下書きは削除されます。

### アクションボタン（屋外向け）

外部 API・センサーを叩くボタン（現在地を取得（GPS）／現場環境からリスク判定／AI診断／周辺インフラ確認／各保存）は、
通常の入力欄と区別できる高コントラスト配色・48px以上の高さに統一しています。実行中は `disabled` ＋スピナー＋処理中文言、
完了後はボタン直下に `12:40取得 / Open-Meteo・国土地理院` のように取得時刻とソースを表示します。

## 2. アーキテクチャ

```text
ブラウザ
├── index.html（GitHub Pages）
│   ├── 機体・操縦者・飛行・点検 ── localStorage
│   ├── 住所検索 ── 国土地理院 住所検索 API
│   ├── 逆ジオコーディング ── BFF（Google Maps Geocoding API）→ 国土地理院（フォールバック）
│   ├── 天候 ── BFF `GET /api/weather`（気象庁アメダス → Open-Meteo 代替）
│   │            ※BFF に接続できないときだけ Open-Meteo を直接取得
│   ├── 標高 ── 国土地理院 標高API
│   ├── DID ── 国土地理院 地理院タイル（did2020）
│   └── 周辺マップ ── 国土地理院 地理院タイル（seamlessphoto / pale）
└── FastAPI BFF
    ├── GET  /api/weather（気象庁アメダス主系 → Open-Meteo 代替・時間予算つき）
    ├── GET  /api/reverse-geocode（Google Maps Geocoding API）
    ├── GET  /api/check-infrastructure（空域 = DID / 空港周辺 + 送電線・鉄塔）
    ├── POST /api/flight-records（status・点検13項目つき飛行記録の保存 / 同期）
    ├── GET  /api/flight-records（保存済み飛行記録の一覧）
    ├── GET  /api/backup / POST /api/backup（localStorage のバックアップ）
    ├── POST /api/parse-log（DJI ログ解析）
    ├── POST /api/export-log（Excel 生成）
    └── POST /api/diagnose（Gemini による飛行前診断）
```

- 一覧・保存・CSV はブラウザ内で完結します。
- 飛行記録は **localStorage を正**とし、保存時に `/api/flight-records` へベストエフォートで同期します
  （現場でオフラインの場合は「端末に保存済み（BFF未同期）」と表示。記録は失われません）。
- BFF が停止していても、記録・検索・CSV 出力は動作します
  （天候は Open-Meteo 直接取得へ、DJI 解析・Excel・インフラ判定・AI 診断のみ失敗）。
- BFF の接続先は **設定タブ** で変更できます（`localStorage` の `drone-log:bff-base-url:v1` に保存）。
  既定値は Tailscale の MagicDNS `https://mac-mini-m4.tail95f7a2.ts.net` です。

## 4. ローカルで確認する

```bash
cd drone-log
python3 -m http.server 8811
# ブラウザで http://localhost:8811/index.html を開く
```

- 初回は **空のストア** で起動します。機体・操縦者を「機体管理」から登録してください。
- 画面確認用のサンプルデータを入れたい場合は `http://localhost:8811/index.html?demo=1` を開きます。
  - `file://` で直接開いた場合もサンプルデータを投入しますが、BFF は CORS の許可外（`Origin: null`）になるため、DJI 解析・Excel・インフラ判定は失敗します。BFF を使う確認は `python3 -m http.server` で配信してください。
- データを初期化する場合は DevTools の Console で次を実行し、再読み込みします。

```js
localStorage.clear();
```

- タブは URL ハッシュで直接開けます（`#entry` / `#log` / `#fleet` / `#help` / `#settings`）。
- `manifest.json` と `icons/` は PWA 用です。PWA のインストールは GitHub Pages 側で行ってください。

## 5. データ保存とバックアップ

- 保存先はブラウザの `localStorage`（キー: `drone-log:mock:v1`）です。
- BFF の接続先は別キー `drone-log:bff-base-url:v1` に保存します（未設定時は既定の MagicDNS）。
- 操縦者の技能証明（資格区分・有効期限・限定解除）は `pilots[]` の各要素に保存します。既存データに項目が無い場合は「未設定」として扱います。
- 設定タブの「データの手動同期」で、`drone-log:` から始まるすべてのキーをBFFの `data/backup.json` に保存し、別端末やデータ削除後に復元できます。復元時はこの端末の `drone-log:` データをバックアップで置き換え、画面を再読み込みします。
- バックアップには操縦者名・技能証明番号・連絡先などの個人情報が含まれます。また `drone-log:bff-base-url:v1` も含まれるため、復元するとBFF接続先も保存時の値に戻ります。BFFの `data/backup.json` は Tailscale 内のサーバーに保存されるため、取扱に注意してください。
- 端末・ブラウザごとにデータが分かれます。共有端末やブラウザのデータ消去で失われるため、定期的に CSV / Excel を出力して保管してください。
- CSV は国交省様式1〜3の記載事項に準拠した**記録・保管用**データです。DIPS 2.0 への直接インポートはできません。
- Excel 出力は BFF の `/api/export-log` を使用します。
- 旧 GAS 版のスプレッドシートデータは、このアプリへ自動移行されません。必要な場合は旧環境から CSV 等で退避してください。

## 6. 外部 API とプライバシー

| 用途 | サービス | 送信する情報 | 備考 |
|---|---|---|---|
| 住所 → 座標 | 国土地理院 住所検索 API | 入力した住所文字列 | API キー不要 |
| 座標 → 住所 | BFF `/api/reverse-geocode`（Google Maps Geocoding API） | 緯度・経度 | キーは BFF の `.env`。失敗時は国土地理院の逆ジオコーダーへフォールバック |
| 天候・風速 | BFF `/api/weather`（気象庁アメダス → Open-Meteo） | 緯度・経度 | キー不要。BFF に繋がらないときだけ PWA が Open-Meteo を直接取得 |
| 標高 | 国土地理院 標高API | 緯度・経度 | API キー不要 |
| DID | 国土地理院 地理院タイル（did2020） | タイル座標 | API キー不要 |
| 空港周辺 | BFF `/api/check-infrastructure`（同梱の空港データ） | 緯度・経度 | 6km/12km は目安。最終判断は DIPS |
| 飛行前診断 | Gemini API（BFF 経由） | 飛行計画・気象・標高・DID・周辺インフラ・機体・資格区分・現場写真（任意） | 氏名・連絡先は送信しない。キーは BFF の `.env` |

- 氏名・連絡先は外部 API へ送信しません。AI 診断では上表の飛行計画などを Gemini へ送ります。
- 逆ジオコーディングは「📍 現在地から住所を取得 (GPS)」「座標から地名を取得」、および離陸場所へ `35.681236, 139.767125` の形式を貼り付けたときに動きます。
- 国土地理院の逆ジオコーディングは、Google のキー未設定・通信失敗時のフォールバックです（市区町村名のみ）。
- 社内ネットワーク等で外部 API が許可されていない場合は、画面に日本語のエラーが表示されます。その場合は緯度・経度・住所を手入力してください。
- 現場環境チェック（周辺インフラ）は 12 秒で打ち切り、BFF が無応答（Tailscale / ローカルネットワークの一時切断など）の場合は
  10 秒のタイムアウトで **1 回だけ自動再試行** します。失敗時は経過秒数と確認事項を画面に表示します。
  BFF 側は OSM 取得と DID 判定を並列化し、全体を 5 秒で打ち切るため、通常は 2〜3 秒で結果が返ります。
- 現場環境チェック（周辺インフラ）は、BFF が **空域（DID / 空港周辺）と送電線・鉄塔** をまとめて判定します。
  UI は **「特定飛行区分」の直上** に置き、「GPS で自動判定してチェックを埋める → 足りないものを手動で選ぶ」順にしています。
  DID・空港周辺に該当すると特定飛行のチェック項目を自動で追加し（解除はしません）、
  DID の場合は **「人または物件から30m未満」も併せて ON** にします（追加のみ。手動で外した場合は戻しません）。
  結果カードに「空域の下限カテゴリー」（例: カテゴリーⅡB以上）を表示します。
  送電線・鉄塔は安全上の要確認であり、法令上の特定飛行ではないためチェックは追加しません。
  DID を判定できなかった場合は「判定不能」と表示し、DIPS での確認を促します。
  時間切れで送電線・鉄塔の有無も分からない場合は「鉄塔 – 基 / 送電線 – 件」と表示し、
  「異常なし」とは表示しません（`power_unknown`）。
- 空港等の周辺は、空港の標点から 6km 以内を「該当（目安）」、12km 以内を「近接（要確認）」として
  表示します。進入表面・転移表面による法令上の境界とは異なるため、最終判断は DIPS で行ってください。

## 7. BFF（FastAPI）の起動

`drone-log-bff` の README を参照してください。

```bash
cd drone-log-bff
.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
```

- ヘルスチェック: `http://127.0.0.1:8000/api/health`
- PWA からの接続先は **設定タブ** で変更します（既定: `https://mac-mini-m4.tail95f7a2.ts.net`）。
- HTTPS の PWA から `http://100.x.x.x:8000` は混在コンテンツで遮断されるため、本番は HTTPS の MagicDNS を指定してください。
- **Chrome の Local Network Access (LNA)**: Chrome 142 以降、GitHub Pages などの公開 HTTPS ページから Tailscale の `100.64.0.0/10` へ接続すると、初回に「ローカル ネットワークへのアクセス」の許可を求められます。**「許可」を選んでください**。許可しないと、CORS の設定が正しくても `Failed to fetch` になります。Safari や `http://localhost` のローカルプレビューでは不要です。
- BFF はステートレスです。DJI ログや画像をディスクへ保存しません。

## 9. 旧 GAS 版からの移行メモ

- `Code.gs` / `appsscript.json` / `.clasp.json` / clasp 用テストは削除済みです。
- 旧 GAS 版の `?api=` パラメータ、`API_CONFIG`、共有トークン、`#sync-status` / `#sheet-link` は廃止しました。
- 旧版でスプレッドシートに保存したデータは、このアプリの `localStorage` へ自動移行されません。
- 旧版のブックマークや GAS のデプロイは不要です。GitHub Pages の URL を使用してください。

## 10. 注意事項

- 本アプリは記録・保管を支援するものであり、法令上の点検要否を保証するものではありません。必ず原典を確認してください。
- `localStorage` はブラウザのプライベートモードや容量制限の影響を受けます。重要な記録は CSV / Excel でバックアップしてください。
- 外部 API の仕様変更・レート制限・ネットワーク遮断により、座標・天候・標高・DID が取得できない場合があります。
